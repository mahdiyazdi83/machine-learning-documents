۲. بدون Label چه چیزی قرار است یاد بگیریم؟

در Supervised Learning، Model از زوج X, y یاد می‌گیرد و Prediction را با جواب واقعی مقایسه می‌کنیم. در Clustering فقط X داریم. Algorithm باید بر اساس شباهت Featureها ساختاری پیشنهاد کند؛ شماره‌های Cluster مثل ۰ و ۱ فقط شناسه‌اند و معنای ذاتی ندارند.

Supervised

Label مرجع داریم؛ Error یا Metric با Ground Truth محاسبه می‌شود.

Unsupervised

Label مرجع نداریم؛ باید Cohesion داخل Cluster و Separation بین Clusterها را بسنجیم.

چالش ارزیابی: کوچک‌بودن یک عدد داخلی لزوماً به معنی مفیدبودن Clusterها برای مسئلهٔ کسب‌وکار نیست. شکل داده، Scale، Outlier و هدف استفاده در تفسیر نتیجه نقش دارند.

۳. همهٔ Clusterها دایره‌ای نیستند

استاد دو خانوادهٔ شهودی را کنار هم گذاشت: روش‌های مبتنی بر Center و روش‌های مبتنی بر Density. K-Means به Center وابسته است و ناحیه‌ها را با نزدیک‌ترین Centroid می‌سازد؛ بنابراین برای Clusterهای فشرده و تقریباً کروی مناسب‌تر است. الگوهای حلقه‌ای، کشیده یا درهم‌تنیده ممکن است با مرزهای مرکز-محور درست جدا نشوند.

دو نگاه به شباهت
Centroid-based

هر Sample به نزدیک‌ترین Center می‌رود.

Density-based

ناحیه‌های پرتراکم می‌توانند شکل نامنظم داشته باشند.

۴. K-Means با تکرار دو حرکت ساده جلو می‌رود

۱. شروع

k Center اولیه انتخاب می‌شود.

۲. Assignment

هر Sample به نزدیک‌ترین Center نسبت داده می‌شود.

۳. Update

میانگین Featureهای هر گروه، Center جدید می‌شود.

c_i = argmin_j ||x_i - μ_j||²     →     μ_j = mean({x_i : c_i = j})

Assignment و Update تکرار می‌شوند تا جابه‌جایی Centerها از tol کمتر شود یا سقف iteration فرا برسد. در فضای دو‌بعدی Centroid از میانگین xها و میانگین yها ساخته می‌شود؛ در ۱۲ بعد همین محاسبه برای ۱۲ Feature انجام می‌شود.

تصویر ذهنی: Centerها حرکت می‌کنند، مالکیت نقطه‌ها عوض می‌شود و دوباره Center محاسبه می‌شود. خودِ دایره‌ای که روی Whiteboard کشیده شد بخشی از Algorithm نیست؛ فقط نمایش ناحیهٔ نزدیک‌بودن بود.

۵. نقطهٔ شروع می‌تواند جواب را عوض کند

اگر Centerهای اولیه بد انتخاب شوند، چند Center ممکن است در یک ناحیه بیفتند یا Algorithm به جواب ضعیفی برسد. جلسه دو راه کنترل را نشان داد:

init='k-means++'

Centerهای اولیه را پخش‌شده‌تر انتخاب می‌کند تا شروع معقول‌تری داشته باشیم.

n_init=5

کل فرایند را پنج بار از شروع‌های متفاوت اجرا و جواب بهتر را نگه می‌دارد.

init می‌تواند Array یا Callable هم باشد، اما Callable باید قرارداد ورودی و خروجی مورد انتظار Library را رعایت کند. در Notebook کلاس از روش استاندارد k-means++ استفاده شد.

۶. Inertia چه چیزی را اندازه می‌گیرد؟

Inertia = Σᵢ ||xᵢ - μ(cᵢ)||²

فاصلهٔ هر Sample تا Center همان Cluster مربع و سپس جمع می‌شود. عدد کمتر یعنی Pointها به Centerهای خود نزدیک‌ترند؛ اما این فقط Cohesion درونی را می‌سنجد.

کمتر بهتر

برای یک Dataset و Scale ثابت.

همیشه نزولی

با افزایش k معمولاً کمتر می‌شود.

حساس به Outlier

مربع فاصله، Point دور را پراثر می‌کند.

دو برداشت ممنوع: Inertia نزدیک صفر به‌تنهایی Cluster مفید را ثابت نمی‌کند؛ و مقایسهٔ خام Inertia بین Datasetهایی با Scale یا تعداد Sample متفاوت معنی روشنی ندارد.

۷. k را با Elbow حدس می‌زنیم، نه اینکه کشف قطعی کنیم

Notebook برای k=2 تا k=9 Model می‌سازد و Inertia را رسم می‌کند. نقطه‌ای که بعد از آن کاهش Inertia کند می‌شود «آرنج» است.

کاهش Inertia با افزایش k
اگر منحنی آرنج واضح نداشته باشد، Domain Knowledge و معیارهای دیگر لازم‌اند.
هشدار خود جلسه: دادهٔ ساختگی واقعاً چهار Center داشت، اما نمودار می‌توانست ۳ یا ۴ را قابل دفاع نشان دهد. Elbow تضمین نمی‌کند «k واقعی» را پس بدهد.

۸. Notebook اول را خط‌به‌خط بخوانیم

با make_blobs تعداد ۱۶۰ Sample، دوازده Feature و چهار Center واقعی ساخته شد. Scatter فقط دو Feature اول را نشان می‌دهد، اما Model روی هر ۱۲ Feature Fit می‌شود.

۹. Center و Cluster در مسئلهٔ واقعی چه معنایی پیدا می‌کنند؟

جانمایی سرویس

تقسیم منطقه

خانه‌ها یا مشتری‌ها را به گروه‌های محلی تقسیم و در صورت نیاز یک Cluster را دوباره ریزتر کنیم.

QC صنعتی

۱۴. انتخاب بازهٔ رنگ با HSV و Trackbar

def select_color(_):
    low = cv2.getTrackbarPos("min_trackbar", "RESULT")
    high = cv2.getTrackbarPos("max_trackbar", "RESULT")
    hsv = cv2.cvtColor(img, cv2.COLOR_BGR2HSV)
    mask = cv2.inRange(hsv, (low, 0, 0), (high, 255, 255))
    result = cv2.bitwise_and(img, img, mask=mask)
    cv2.imshow("RESULT", result)

cv2.namedWindow("RESULT")
cv2.createTrackbar("min_trackbar", "RESULT", 0, 179, select_color)
cv2.createTrackbar("max_trackbar", "RESULT", 179, 179, select_color)
select_color(0)
cv2.waitKey(0)
cv2.destroyAllWindows()

۱۷. Contour از Pixel سفید به مرز و Bounding Box می‌رسد

برای تصویر رقم‌ها، ابتدا Gray و Threshold ساخته شد، سپس Contourهای خارجی پیدا شدند. برای هر Contour، boundingRect یک مستطیل (x, y, w, h) می‌دهد و Slice متناظر از تصویر استخراج می‌شود. همین Pattern پایهٔ Object Counting و ساخت Crop برای Classifier است.

gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
_, thresh = cv2.threshold(gray, 127, 255, cv2.THRESH_BINARY)
contours, hierarchy = cv2.findContours(thresh, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)

for cnt in contours:
    x, y, w, h = cv2.boundingRect(cnt)
    region = img[y:y+h, x:x+w]
    cv2.rectangle(img, (x, y), (x+w, y+h), (0, 0, 255), 2)
    cv2.drawContours(img, [cnt], 0, (0, 255, 0), 2)
تفاوت با فایل فعلی: Script آستانه را محاسبه می‌کند اما به‌اشتباه gray را به findContours می‌دهد. در مثال سیاه‌وسفید ممکن است ظاهراً جواب بدهد، ولی Pipeline درست باید تصویر Binary یعنی thresh را بدهد.

۱۸. Template Matching: این Patch کجای تصویر تکرار شده؟

در مثال Mario، تصویر Coin کوچک روی تصویر بزرگ Slide می‌شود و برای هر موقعیت یک Score شباهت ساخته می‌شود. خروجی matchTemplate خودِ تصویر Boxدار نیست؛ یک Response Map است و باید بهترین نقطه یا نقاط بالاتر از Threshold از آن استخراج شوند.

img = cv2.imread("mario/img.png")
template = cv2.imread("mario/template.png")
response = cv2.matchTemplate(img, template, cv2.TM_CCOEFF_NORMED)
_, score, _, top_left = cv2.minMaxLoc(response)
h, w = template.shape[:2]
bottom_right = (top_left[0] + w, top_left[1] + h)
cv2.rectangle(img, top_left, bottom_right, (0, 255, 0), 2)
print(score)
محدودیت: تغییر Scale، Rotation، نور و شکل می‌تواند Match را ضعیف کند. Template Matching برای الگوی نسبتاً ثابت مناسب است، نه هر نوع Object Detection.

۱۹. از Template ثابت به Keypoint و Descriptor

Feature Detectorهایی مثل SIFT، SURF و ORB به‌جای مقایسهٔ کل Patch، نقطه‌های متمایز را پیدا و اطراف آن‌ها Descriptor می‌سازند. این Descriptorها برای Match مقاوم‌تر به تغییر View به کار می‌روند. در جلسه بیشتر مسیر استفاده و خروجی Keypoint/Descriptor دیده شد.

←

Verify Geometry
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
sift = cv2.SIFT_create()
keypoints, descriptors = sift.detectAndCompute(gray, None)
result = cv2.drawKeypoints(gray, keypoints, img)
cv2.imwrite("sift_keypoints.jpg", result)
نام و API فایل فعلی هم‌خوان نیست: متغیر sift با cv.SURF_create() ساخته شده؛ این فراخوان در OpenCV معمول استاندارد نیست. اگر هدف SIFT است از SIFT_create استفاده شود؛ اگر واقعاً SURF لازم است، build سازگار OpenCV-contrib و API همان نسخه باید بررسی شود.

۲۰. YOLO: از Feature دستی به Detector یادگرفته‌شده

YOLO با یک بار Inference، Box، Class و Confidence چند Object را برمی‌گرداند. فایل 10.py Model را اجرا می‌کند، اما خروجی را رسم یا ذخیره نمی‌کند. روش مستقیم، استفاده از result.plot() است.

from ultralytics import YOLO
import cv2
model = YOLO("yolo26n.pt")
result = model("img_2.png")[0]

annotated = result.plot()
cv2.imshow("YOLO Detection", annotated)
cv2.waitKey(0)
cv2.destroyAllWindows()
Classification

برای کل تصویر یک Label یا Probability می‌دهد.

Detection

برای هر Object، Box + Class + Confidence می‌دهد.

Pose

علاوه بر Box، Keypointهای بدن می‌دهد و Model مخصوص Pose می‌خواهد.

Checkpoint مهم است: بررسی امن Metadata نشان داد yolo12n.pt و yolo26n.pt موجود هر دو DetectionModel هستند. پس در 11.py عنوان «YOLO12 Pose» و خواندن result.keypoints با Checkpoint فعلی سازگار نیست؛ برای Pose باید Model مخصوص Pose استفاده شود.

۲۱. Haar Cascade: Detector کلاسیک با Positive و Negative

در پایان ضبط، منطق Dataset کلاسیک مطرح شد: Positiveها تصویرهای دارای Object هدف و Negativeها تصویرهای فاقد آن هستند. Cascade از Featureهای ساده و مرحله‌های پی‌درپی استفاده می‌کند تا Candidateهای نامحتمل را سریع حذف کند.

۱. جمع‌آوری

نمونه‌های Positive باید Object هدف را داشته باشند و Negativeها صحنه‌های فاقد آن را پوشش دهند.

۲. فهرست‌سازی

مسیر تصویرها در فایل‌های متنی ثبت می‌شود تا ابزارهای خط فرمان بتوانند Dataset را بخوانند.

۳. Annotation

با ابزار opencv_annotation دور Object هدف Rectangle کشیده و نمونهٔ درست تأیید می‌شود؛ در توضیح کلاس کلیدهای تأیید، حذف و رفتن به تصویر بعد مرور شدند.

۴. ساخت و Train

Annotationها به فرمت نمونه‌های آموزشی تبدیل و سپس Cascade مرحله‌به‌مرحله Train می‌شود.

تکلیف انتهای ضبط سوم: ابزارهای Annotation/Training همراه نسخهٔ کامل OpenCV بررسی و برای جلسهٔ بعد یک Pipeline کوچک Positive/Negative آماده شود. نام و گزینه‌های Commandها به Build نصب‌شده وابسته‌اند؛ قبل از اجرای دستور، وجود Binary و Help همان نسخه را کنترل کن.
detector = cv2.CascadeClassifier("haarcascade_smile.xml")
cap = cv2.VideoCapture(0)
while cap.isOpened():
    ok, frame = cap.read()
    if not ok: break
    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    detections = detector.detectMultiScale(gray)
    for x, y, w, h in detections:
        cv2.rectangle(frame, (x, y), (x+w, y+h), (255, 0, 0), 2)
    cv2.imshow("frame", frame)
    if cv2.waitKey(1) & 0xFF == ord("q"): break
cap.release()
cv2.destroyAllWindows()
نام فایل را جدی بگیر: Script فعلی haarcascade_smile.xml را Load می‌کند، نه فایل Face. نام متغیر face_detector گمراه‌کننده است و باید با Model واقعی هماهنگ شود.

۲۴. خودآزمایی مفهومی

چرا Cluster ID صفر و یک معنای Class واقعی ندارد؟

چون Algorithm فقط گروه‌ها را شماره‌گذاری کرده است. جابه‌جایی شماره‌ها هیچ تغییری در ساختار Clustering ایجاد نمی‌کند.

دو حرکت تکراری K-Means چیست؟

نسبت‌دادن هر Sample به نزدیک‌ترین Centroid و سپس محاسبهٔ دوبارهٔ Centroid هر گروه با میانگین Featureها.

چرا Inertia با افزایش k کم می‌شود؟

Centerهای بیشتر معمولاً فاصلهٔ هر Point تا نزدیک‌ترین Center را کمتر می‌کنند؛ در حد افراطی هر Point می‌تواند Center خودش باشد.

چرا Elbow جواب قطعی نیست؟

ممکن است شکست منحنی مبهم باشد، Clusterها هم‌پوشان باشند یا هدف عملی با فشردگی هندسی یکسان نباشد.

در Segmentation تصویری Notebook، هر Sample و Feature چیست؟

هر Pixel یک Sample و شدت Gray آن یک Feature است. در نسخهٔ رنگی می‌توان Channelها را Feature در نظر گرفت.

چرا RGB برای انتخاب «نوع رنگ» از HSV سخت‌تر است؟

در RGB نوع رنگ و روشنایی در سه Channel درهم‌اند؛ در HSV، Hue نوع رنگ را جدا می‌کند و Rangeگذاری شهودی‌تر می‌شود.

فرق Threshold و Adaptive Threshold چیست؟

اولی یک مرز سراسری دارد؛ دومی Threshold را از همسایگی محلی می‌سازد و برای نور ناهمگون مناسب‌تر است.

چرا Template Matching جای YOLO را نمی‌گیرد؟

Template به Patch ثابت و Scale/Rotation مشابه وابسته است؛ YOLO از داده الگوهای پیچیده‌تر Object، Box و Class را یاد می‌گیرد.

چرا yolo12n.pt فعلی Keypoint نمی‌دهد؟

چون Metadata آن DetectionModel است. Keypoint به Checkpoint مخصوص Pose نیاز دارد.

۱. Classification یعنی انتخاب میان جواب‌های گسسته

در Regression خروجی می‌تواند هر عددی روی یک بازه باشد. در Classification خروجی یکی از Classهای مشخص است. دو Class حالت Binary و بیش از دو Class حالت Multi-class نام دارد. Label ممکن است متن باشد، اما مدل معمولاً آن را به عدد داخلی تبدیل می‌کند.

Binary

دو جواب مانند سالم/بیمار یا قبول/رد.

Multi-class

یک جواب از چند Class؛ مانند نوع حیوان یا گروه بیماری.

Multi-label

چند Label می‌توانند هم‌زمان برای یک Sample درست باشند؛ این حالت با Multi-class یکی نیست.

Notebook اول آرایه‌ای از اندازه‌ها را به Labelهای healthy، sick و a وصل می‌کند. LabelEncoder این نام‌ها را بر اساس ترتیب داخلی به ۰، ۱ و ۲ تبدیل می‌کند. این اعداد شناسهٔ Class هستند؛ فاصلهٔ ۰ تا ۲ به معنی «دو برابر دورتر» نیست.

size = np.array([3, 4, 7, 9, 11, 34, 36, 37, 39, 42, 200]).reshape(-1, 1)
result = np.array(["healthy", "healthy", "healthy", "healthy", "healthy",
                   "sick", "sick", "sick", "a", "a", "a"])
encoder = LabelEncoder()
y = encoder.fit_transform(result)
نکتهٔ مهم: LabelEncoder برای Target مناسب است، اما استفاده از شناسه‌های آن به‌عنوان Feature می‌تواند ترتیب و فاصلهٔ مصنوعی وارد مدل کند.

۲. چرا Linear Regression جای Classifier را نمی‌گیرد؟

یک ایدهٔ ساده این است که خط Regression را برازش بدهیم و هر مقدار کمتر از ۰٫۵ را Class صفر و بقیه را Class یک بنامیم. مشکل اینجاست که خروجی خط به بازهٔ صفر و یک محدود نیست. یک Sample دورافتاده می‌تواند شیب خط را تغییر دهد و Threshold را در جای نامناسبی قطع کند. در مثال سه‌کلاسهٔ Notebook نیز تبدیل همهٔ مقدارهای بالاتر از ۰٫۵ به ۱ عملاً Class شمارهٔ ۲ را از بین می‌برد.

از Score خطی تا احتمال
z = wᵀx + b←Sigmoid←0 < p < 1←Threshold←Class

Sigmoid هر عدد حقیقی را به بازهٔ صفر تا یک می‌برد. در صفر مقدارش ۰٫۵ است، برای عددهای منفی به صفر نزدیک می‌شود و برای عددهای مثبت به یک. Logistic Regression ابتدا ترکیب خطی Featureها را می‌سازد و سپس آن را به Probability تبدیل می‌کند.

σ(z) = 1 / (1 + exp(−z))
def logistic(z):
    return 1 / (1 + np.exp(-z))

z = np.arange(-10, 11)
p = logistic(z)
نام مدل گمراه‌کننده است: Logistic Regression برای Classification استفاده می‌شود. واژهٔ Regression به مدل‌کردن Log-Odds با یک تابع خطی اشاره دارد، نه نوع خروجی نهایی.

۳. predict، predict_proba و Threshold یک چیز نیستند

predict_proba برای هر Sample یک Probability به ازای هر Class می‌دهد. مجموع Probabilityهای هر ردیف تقریباً یک است. predict معمولاً Class با بیشترین Score/Probability را برمی‌گرداند. Confidence در گفتار کلاس همان بزرگی احتمال Class انتخاب‌شده است، اما Probability بزرگ لزوماً Calibration خوب را تضمین نمی‌کند.

یک Label نهایی برای هر Sample؛ مناسب تصمیم، اما اطلاعات میزان اطمینان را پنهان می‌کند.

بردار Probabilityها؛ برای تغییر Threshold، رتبه‌بندی و تحلیل Confidence مفید است.

لگاریتم Probabilityها؛ از نظر عددی برای بعضی محاسبات پایدارتر است.

clf = LogisticRegression()
clf.fit(X_train, y_train)
y_label = clf.predict(X_test)
y_proba = clf.predict_proba(X_test)
confidence = y_proba.max(axis=1)

Threshold پیش‌فرض Binary معمولاً ۰٫۵ است، اما انتخاب درست به هزینهٔ خطا بستگی دارد. پایین‌آوردن Threshold معمولاً Recall را زیاد و Precision را کم می‌کند؛ بالابردنش جهت عکس دارد. Accuracy، Precision، Recall و F1 باید متناسب با مسئله خوانده شوند، نه به‌عنوان چهار عدد تزئینی.

Probability با قطعیت یکی نیست: مقدار ۰٫۹ فقط وقتی معنای قابل‌اعتماد دارد که مدل Calibration مناسبی داشته باشد و دادهٔ استفاده با دادهٔ آموزش هم‌توزیع باشد.

۴. Cross-Entropy؛ Probability اشتباه را جریمه می‌کنیم

برای آموزش Classifier فقط درست یا غلط بودن Label کافی نیست. مدلی که جواب درست را با احتمال ۰٫۵۱ داده، با مدلی که همان جواب را با احتمال ۰٫۹۹ داده رفتار یکسانی ندارد. Cross-Entropy احتمال Class درست را وارد Log می‌کند؛ هرچه مدل به جواب درست Probability کمتری بدهد، Loss بزرگ‌تر می‌شود.

L = − Σᵢ yᵢ log(pᵢ)

در Binary Classification شکل کامل معمولاً هر دو حالت را دارد: −[y log(p) + (1−y) log(1−p)]. در Multi-class، y به‌صورت One-hot مشخص می‌کند کدام Probability باید در Loss نقش اصلی داشته باشد. log_loss در scikit-learn همین منطق را پیاده می‌کند.

Class Weight

Loss نمونه‌های Class کم‌تعداد یا مهم‌تر را وزن بیشتری می‌دهد.

L1

بعضی Coefficientها را به صفر نزدیک یا دقیقاً صفر می‌کند.

L2

وزن‌های بزرگ را نرم‌تر جریمه می‌کند و پیش‌فرض رایج Logistic Regression است.

Class Weight راهی برای اصلاح هزینهٔ خطاست، نه ساختن اطلاعات جدید. اگر Class کوچک پوشش مناسبی در Train ندارد، وزن بیشتر به‌تنهایی جای دادهٔ نماینده را نمی‌گیرد.

۵. ColumnTransformer؛ هر ستون مسیر مناسب خودش را می‌رود

Notebook دوم DataFrame کوچکی با سه ستون عددی و یک ستون male/female می‌سازد. ستون‌های عددی با StandardScaler و ستون دسته‌ای با OneHotEncoder آماده می‌شوند. خروجی این دو شاخه کنار هم قرار می‌گیرد و یک ماتریس Feature واحد می‌سازد.

a, b, c←StandardScaler←Featureهای عددی
d←OneHotEncoder←Featureهای دسته‌ای
preprocess = ColumnTransformer(
    transformers=[
        ("scaler", StandardScaler(), ["a", "b", "c"]),
        ("encoder", OneHotEncoder(handle_unknown="ignore"), ["d"]),
    ]
)

handle_unknown="ignore" در نسخهٔ تمیز بالا اضافه شده تا Category تازه در Test یا Production باعث خطا نشود. Transformerها باید فقط روی Train fit شوند؛ میانگین و انحراف معیار Test نباید وارد Scaling شود.

چرا LabelEncoder اینجا مناسب نبود؟ ColumnTransformer ورودی ستونی دوبعدی می‌دهد، اما LabelEncoder برای Target یک‌بعدی طراحی شده است. در ویدئو این تلاش خطا می‌دهد و با OneHotEncoder جایگزین می‌شود.

۶. Pipeline قرارداد یکسان Train و Predict را نگه می‌دارد

اگر Preprocessing را دستی اجرا کنیم، ممکن است هنگام Prediction یک مرحله یا ترتیبش را فراموش کنیم. Pipeline Transformerها و Model را در یک شیء قرار می‌دهد. هنگام fit، Transformerها فقط از Train یاد می‌گیرند؛ هنگام predict همان تبدیل یادگرفته‌شده بدون Fit دوباره اجرا می‌شود.

pipeline = Pipeline([
    ("preprocessor", preprocess),
    ("model", LogisticRegression()),
])

pipeline.fit(x_train, y_train)
y_pred_train = pipeline.predict(x_train)
y_pred_test = pipeline.predict(x_test)

Notebook هشت ردیف تکراری دارد و Split آن بسیار کوچک است؛ پس Accuracy حاصل را نباید به‌عنوان برآورد پایدار تعمیم تفسیر کرد. هدف این مثال نشان‌دادن اتصال Componentهاست، نه ارائهٔ یک Benchmark.

مرز یادگیری پارامترها
Train خام←fit Preprocessor←transform←fit Model
Test فقط از پارامترهای یادگرفته‌شده عبور می‌کند؛ در ساخت آن‌ها سهم ندارد.

۷. Estimator سفارشی باید قرارداد scikit-learn را رعایت کند

ضبط دوم نشان می‌دهد Pipeline فقط با Modelهای آماده محدود نیست. یک Class سفارشی می‌تواند با ارث‌بری از BaseEstimator و Mixin مناسب در اکوسیستم scikit-learn قرار بگیرد. Hyperparameterها در __init__ ذخیره می‌شوند، fit شیء را برمی‌گرداند و predict برای Sampleهای تازه خروجی می‌سازد.

class CustomClassifier(BaseEstimator, ClassifierMixin):
    def __init__(self, alpha=1.0):
        self.alpha = alpha

    def fit(self, X, y):
        self.classes_ = np.unique(y)
        # پارامترهای یادگرفته‌شده با پسوند _ ذخیره می‌شوند
        return self

    def predict(self, X):
        raise NotImplementedError

    def predict_proba(self, X):
        raise NotImplementedError

فایل 03.py عمداً اسکلت ناقص دارد و متدها pass هستند؛ پس Model قابل‌آموزش واقعی نیست. همچنین CustomClassifier در آن Hyperparameterهای اجباری C و alpha دارد، اما داخل Pipeline بدون آرگومان ساخته شده و اجرا خطا می‌دهد.

چرا BaseEstimator مهم است؟ پیاده‌سازی استاندارد get_params/set_params را فراهم می‌کند تا Pipeline، Clone و ابزارهای جست‌وجوی Hyperparameter بتوانند با Estimator کار کنند.

۸. SVM فقط یک خط جداکننده نمی‌خواهد؛ بیشترین Margin را می‌خواهد

برای دادهٔ Linearly Separable چند خط می‌توانند Classها را جدا کنند. SVM خط یا Hyperplaneای را ترجیح می‌دهد که فاصله‌اش از نزدیک‌ترین Sampleهای دو طرف بیشترین باشد. این فاصله Margin است. Sampleهایی که مرز Margin را تعیین می‌کنند Support Vector نام دارند.

شماتیک Margin و Support Vector

در Soft-Margin SVM اجازه می‌دهیم بعضی Sampleها داخل Margin یا حتی سمت اشتباه قرار بگیرند. این انعطاف برای دادهٔ دارای Noise ضروری است. Model نباید برای یک نقطهٔ پرت، مرزی بسیار پیچیده بسازد و Generalization را قربانی کند.

ویژگی مهم: جایگاه مرز بیش از همه از Support Vectorها اثر می‌گیرد. نقاط دور از Margin معمولاً تغییر کوچکی در مرز ایجاد نمی‌کنند.

۹. Kernel Trick؛ جدایی سخت را در فضای دیگری ساده کنیم

اگر Classها با خط مستقیم جدا نشوند، می‌توان داده را به فضای Feature غنی‌تری نگاشت کرد. الگویی که در دو بُعد حلقه‌ای است ممکن است در سه بُعد با یک صفحه جدا شود. Kernel این شباهت در فضای جدید را بدون ساخت صریح همهٔ Featureهای آن فضا محاسبه می‌کند.

فضای ۲بعدیِ غیرخطی←Kernel Mapping←فضای پربُعدتر←Hyperplane خطی
Kernelرفتارپارامترهای حساس
linearمرز خطی؛ مناسب وقتی Featureها از قبل جدایی خوبی دارند.C
polyتعامل‌های چندجمله‌ای و مرزهای خمیده.C، degree، gamma، coef0
rbfمرز محلی و منعطف بر اساس فاصله.C و gamma
sigmoidرفتاری شبیه تابع فعال‌سازی؛ همیشه انتخاب مناسب نیست.C، gamma و coef0
RBF(x, x′) = exp(−γ ||x − x′||²)

Notebook و 06.py Kernelهای Linear، Polynomial، RBF و Sigmoid را روی دادهٔ make_moons مقایسه می‌کنند. شکل مرز نتیجهٔ هم‌زمان Kernel و Hyperparameterهاست؛ نام Kernel به‌تنهایی پیچیدگی را مشخص نمی‌کند.

۱۰. C و gamma چه چیزی را کنترل می‌کنند؟

C بزرگ: خطاهای Train گران‌ترند و Model تلاش بیشتری برای درست‌کردن Sampleها می‌کند؛ Margin معمولاً تنگ‌تر و خطر Overfitting بیشتر می‌شود. C کوچک: خطا تحمل می‌شود و Margin نرم‌تر است.

در RBF، gamma بزرگ اثر هر Sample را محلی‌تر و مرز را پرپیچ‌وخم‌تر می‌کند. gamma کوچک اثر گسترده‌تری می‌دهد و مرز نرم‌تر می‌شود.

برای Polynomial Kernel درجهٔ تعامل‌ها را تعیین می‌کند. درجهٔ بالاتر ظرفیت را زیاد می‌کند، اما هزینهٔ محاسبات و خطر Overfitting نیز بیشتر می‌شود.

SVM به Scale حساس است، چون فاصله و Dot Product در تصمیم نقش دارند. اگر یک Feature دامنهٔ هزاران و دیگری دامنهٔ یک داشته باشد، Feature بزرگ‌تر هندسه را تسخیر می‌کند. StandardScaler باید داخل Pipeline و فقط روی Train Fit شود.

svm_pipeline = Pipeline([
    ("scaler", StandardScaler()),
    ("model", SVC(kernel="rbf", C=1, gamma="scale")),
])

svm_pipeline.fit(X_train, y_train)
y_pred = svm_pipeline.predict(X_test)
یک پارامتر در همهٔ Kernelها اثر یکسان ندارد: مثلاً gamma در Linear Kernel نقشی ندارد. Grid Search خام ممکن است ترکیب‌های بی‌اثر را بیهوده امتحان کند.

۱۱. Hyperparameter Search باید داخل Cross-Validation انجام شود

parameters = {

grid_model = GridSearchCV(

grid_model.fit(X_train, y_train)

Data Leakage در Search: اگر Scaling پیش از GridSearch روی کل داده Fit شود، Foldهای Validation اطلاعاتی از بقیهٔ داده دیده‌اند. Transformer و SVC باید با هم داخل Pipeline قرار بگیرند و خود Pipeline جست‌وجو شود.

۱۲. از خط دوبعدی تا صفحهٔ سه‌بعدی و مسئلهٔ چندکلاسه

در دو Feature، مرز خطی یک خط است؛ در سه Feature یک صفحه؛ و در فضای nبعدی Hyperplane. Scriptهای 10.py و 11.py دادهٔ سه‌بعدی می‌سازند و صفحات یا حجم‌های تصمیم را نمایش می‌دهند. هدف شکل‌ها دیدن این نکته است که «مرز» با افزایش Feature ناپدید نمی‌شود؛ فقط دیگر نمی‌توانیم مستقیم آن را رسم کنیم.

SVC برای Multi-class چند مسئلهٔ Binary می‌سازد. decision_function_shape="ovo" به راهبرد One-vs-One اشاره دارد: هر جفت Class با هم مقایسه می‌شوند. در سه Class سه مدل جفتی داریم. این صفحات را نباید ساده‌انگارانه «یک صفحه برای هر Class» نامید.

تعداد Classifierهای One-vs-One
k classes → k(k − 1) / 2 binary classifiers
برای ۳ Class، سه مقایسهٔ دوتایی ساخته می‌شود.
Decision Score با Probability فرق دارد: SVC به‌طور پیش‌فرض probability=False است. decision_function فاصلهٔ علامت‌دار از مرز را می‌دهد؛ Probability فقط با فعال‌کردن Calibration داخلی و هزینهٔ Fit بیشتر فراهم می‌شود.

۱۳. One-Class SVM و DBSCAN؛ وقتی Label عادی/غیرعادی نداریم

در پایان ضبط دوم، One-Class SVM برای Outlier Detection معرفی می‌شود. Model عمدتاً شکل ناحیهٔ دادهٔ عادی را یاد می‌گیرد و نقاط بیرون آن را غیرعادی علامت می‌زند. این مسئله با SVC دودسته‌ای فرق دارد، چون معمولاً نمونهٔ Labelخوردهٔ کافی از تمام Anomalyها نداریم.

روشایدهپارامتر حساس
One-Class SVMساخت مرزی دور دادهٔ عادی در فضای Kernel.nu، gamma و Scale
DBSCANخوشه‌های چگال را پیدا و نقاط بدون همسایهٔ کافی را Noise می‌نامد.eps و min_samples
LOFچگالی محلی هر نقطه را با همسایه‌هایش مقایسه می‌کند.n_neighbors

مدرس DBSCAN و جدول مقایسهٔ روش‌های Outlier را در حد اتصال مفهومی مطرح می‌کند؛ پیاده‌سازی کامل آن در فایل جلسه وجود ندارد. نقاط «غیرعادی» نیز الزاماً خطای داده نیستند و قبل از حذف باید معنای دامنه‌ای آن‌ها بررسی شود.

فرق predict و predict_proba چیست؟

Support Vector چه نقشی در SVM دارد؟

نمونه‌های نزدیک Margin هستند که جای مرز تصمیم را تعیین می‌کنند؛ نقاط دورتر معمولاً اثر مستقیم کمتری دارند.

C بزرگ همیشه بهتر است؟

gamma بزرگ در RBF چه اثری دارد؟

اثر هر Sample را محلی‌تر و مرز را منعطف‌تر می‌کند؛ اگر بیش از حد بزرگ باشد خطر Overfitting بالا می‌رود.

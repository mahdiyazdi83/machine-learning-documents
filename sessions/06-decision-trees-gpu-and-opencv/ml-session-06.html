۲. چرا Decision Tree قابل توضیح‌تر است؟

در ابتدای جلسه بحث از Interpretability شروع می‌شود. در مدل خطی می‌توانیم Coefficientها را ببینیم، اما وقتی رابطه‌ها پیچیده و شرطی می‌شوند، توضیح یک عدد برای هر Feature همیشه کافی نیست. Decision Tree تصمیم را به مجموعه‌ای از شرط‌های قابل‌ردگیری تبدیل می‌کند.

مدل خطی

اثر Featureها را در یک ترکیب عددی مثل w₁x₁ + w₂x₂ جمع می‌کند. خواندن Coefficient مفید است، اما Interactionهای شرطی را مستقیم نشان نمی‌دهد.

Decision Tree

مسیر هر پیش‌بینی را می‌توان سؤال‌به‌سؤال دنبال کرد: این نمونه از کدام شرط عبور کرد و چرا به این Leaf رسید؟

مزیت عملی: برای یک نمونهٔ خاص می‌توان مسیر Root تا Leaf را نشان داد. این توضیح محلی، تصمیم مدل را برای دانشجو یا متخصص حوزه قابل پیگیری می‌کند.
اما شفاف‌بودن مساوی درست‌بودن نیست: یک درخت عمیق هم قابل رسم است، ولی ممکن است دادهٔ آموزش را حفظ کرده باشد و روی ورودی جدید ضعیف عمل کند.

۳. از Graph به Tree: Root، Edge، Node و Leaf

مدرس قبل از ورود به الگوریتم، Tree را به‌عنوان نوع خاصی از Graph معرفی می‌کند. Graph از Nodeها و Edgeها ساخته می‌شود. Tree از یک Root شروع می‌شود، مسیر چرخه‌ای ندارد و رابطهٔ والد–فرزند در آن روشن است. Node داخلی سؤال می‌پرسد و Leaf نتیجهٔ نهایی را نگه می‌دارد.

Directed / Undirected

در Graph جهت‌دار، Edge مسیر مشخصی دارد؛ مثل Link از یک صفحه به صفحهٔ دیگر. در Graph بدون‌جهت ارتباط دوطرفه در نظر گرفته می‌شود.

Weighted / Unweighted

Edge می‌تواند وزنی مثل فاصله، هزینه یا شدت ترافیک داشته باشد؛ یا فقط وجود اتصال را نشان دهد.

Path و Shortest Path

مسیر دنباله‌ای از Edgeها بین Nodeهاست. الگوریتم‌های مسیریابی با توجه به وزن، مسیر کم‌هزینه‌تر را پیدا می‌کنند.

۴. مثال دستی: سؤال‌ها چطور مسیر می‌سازند؟

در مثال دستی جلسه، چند Feature عددی مثل سن، BMI و یک شاخص آزمایشگاهی کنار Label قرار می‌گیرند. درخت ابتدا سؤال اثرگذارتری مثل «سن بیشتر از ۵۶ است؟» را انتخاب می‌کند؛ بعد هر سمت را با سؤال دیگری جدا می‌کند. یک نمونه فقط یک مسیر را طی می‌کند، نه همهٔ Nodeها را.

اگر یک شرط گروه‌ها را کاملاً جدا نکند، این شکست نیست. Child حاصل دوباره با Feature یا Threshold دیگری تقسیم می‌شود. درخت مجموعه‌ای از تقسیم‌های محلی است که با هم یک قانون پیچیده‌تر می‌سازند.

شرط‌ها حقیقت پزشکی یا کسب‌وکاری نیستند: Threshold از داده و معیار الگوریتم آمده است. اینکه مدل «سن» را اول انتخاب کرده، به‌تنهایی اثبات رابطهٔ علّی یا نظر متخصص حوزه نیست.

این جست‌وجو برای Featureهای مجاز تکرار می‌شود. Split برنده فقط Threshold خوبی روی یک ستون نیست؛ باید بعد از درنظرگرفتن تعداد نمونه‌های هر Child، کمترین ناخالصی وزنی یا بیشترین کاهش ناخالصی را بسازد.

۶. Gini و Entropy چه چیزی را اندازه می‌گیرند؟

هدف این دو معیار اندازه‌گیری مخلوط‌بودن Classها داخل یک Node است. وقتی همهٔ نمونه‌ها از یک Class باشند، Node خالص و Impurity صفر است. هرچه نسبت Classها به هم نزدیک‌تر شود، عدم قطعیت بالاتر می‌رود.

Gini Impurity
Gini = 1 − Σ pᵢ²

احتمال خطا در برچسب‌گذاری تصادفی بر اساس توزیع Classها را بازتاب می‌دهد. معیار پیش‌فرض DecisionTreeClassifier است.

Entropy
Entropy = −Σ pᵢ log₂(pᵢ)

۸. Decision Tree فقط برای Classification نیست

در پایان بخش مفهومی ضبط اول، مدرس تأکید می‌کند که ساختار Tree برای Regression هم قابل استفاده است؛ مثلاً پیش‌بینی قیمت، فشار خون یا یک مقدار پیوستهٔ دیگر. تفاوت اصلی در نوع پاسخ Leaf و معیاری است که کیفیت Split را می‌سنجد.

Classification Tree

Leaf یک Class یا توزیع احتمال Classها را می‌دهد و Split با معیارهایی مثل Gini یا Entropy سنجیده می‌شود.

Regression Tree

Leaf یک مقدار عددی می‌دهد. هدف Split این است که مقدارهای y داخل Childها به هم نزدیک‌تر شوند و خطای عددی کاهش پیدا کند.

تکمیل کوتاه برای خواندن خروجی Regression Tree

در پیاده‌سازی رایج و با Criterion مربعی، Prediction یک Leaf میانگین yهای آموزشی رسیده به آن است. بنابراین خروجی Tree به‌صورت ناحیه‌های پله‌ای تغییر می‌کند، نه یک خط صاف. این توضیح برای کامل‌کردن مفهوم Regression Tree به مستند افزوده شده است.

همان منطق، پاسخ متفاوت: در هر دو حالت Feature و Threshold انتخاب می‌شوند؛ چیزی که عوض می‌شود تعریف «بهترشدن گروه‌ها» و خروجی نهایی Leaf است.

۹. Pre-pruning و Post-pruning؛ درخت را کجا مهار کنیم؟

مدرس رشد کنترل‌نشده را با Overfitting پیوند می‌دهد. دو نگاه اصلی داریم: از ابتدا اجازه ندهیم شاخه‌های خیلی ریز ساخته شوند، یا ابتدا درخت را بسازیم و بعد شاخه‌های کم‌ارزش را حذف کنیم.

با پارامترهایی مثل max_depth، min_samples_split، min_samples_leaf و min_impurity_decrease جلوی رشد بی‌قاعده را همان زمان Fit می‌گیریم.

درخت بزرگ‌تر ساخته می‌شود و سپس شاخه‌هایی که ارزش تعمیم ندارند حذف می‌شوند. در scikit-learn پارامتر ccp_alpha ابزار Cost-Complexity Pruning است؛ این نام در کد جلسه استفاده نشده و این توضیح به‌عنوان تکمیل مستقیم مفهوم Pruning آمده است.

۱۰. ساخت DecisionTreeClassifier روی Iris

مثال کدنویسی اصلی از Iris استفاده می‌کند: ۱۵۰ نمونه، چهار Feature عددی و سه Class متوازن با ۵۰ نمونه برای هر گونه. Notebook ابتدا روی همهٔ X Fit می‌کند و سپس روی همان X پیش‌بینی می‌گیرد.

from sklearn.datasets import load_iris
from sklearn.tree import DecisionTreeClassifier, plot_tree
import matplotlib.pyplot as plt

iris = load_iris()
X, y = iris.data, iris.target
clf = DecisionTreeClassifier(criterion="entropy")
clf.fit(X, y)
y_pred = clf.predict(X)

plt.figure(figsize=(12, 12))
plot_tree(clf, filled=True,
          feature_names=iris.feature_names,
          class_names=iris.target_names,
          rounded=True)
plt.show()

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42)

clf = DecisionTreeClassifier(max_depth=3, random_state=42)
clf.fit(X_train, y_train)
y_pred = clf.predict(X_test)
print(classification_report(y_test, y_pred,
                            target_names=iris.target_names))
نکتهٔ تکمیلی: در اجرای کنترلی این مستند، Tree بدون محدودیت با Split ثابت روی train امتیاز ۱٫۰۰ و روی test حدود ۰٫۹۳ گرفت. این عدد Benchmark رسمی جلسه نیست؛ فقط نشان می‌دهد فاصلهٔ train و test واقعاً وجود دارد.
Sampling باید نمایندهٔ دنیای واقعی باشد: مدرس مثال می‌زند که اگر آموزش فقط از افراد زیر ۶۰ سال آمده باشد، نمی‌توان با خیال راحت دربارهٔ فرد ۸۰ ساله نتیجه گرفت. train و test باید پوشش مناسبی از گروه‌های مهم داشته باشند؛ Cross-Validation هم مدل را روی چند ترکیب متفاوت می‌سنجد تا نتیجه به یک Split خاص وابسته نباشد.

Correlation

رابطهٔ آماری دوتایی، معمولاً خطی، بین ستون‌ها را نشان می‌دهد. ممکن است با Importance هم‌جهت نباشد.

خروجی دقیق ثابت نیست: Notebook برای Tree مقدار random_state تعیین نکرده است. در Splitهای هم‌ارزش، ترتیب تصادفی Featureها می‌تواند ساختار و Importance ذخیره‌شده را بین اجراها تغییر دهد.
کاربردی که در گفتار مطرح شد: می‌توان Importance را سرنخی برای Feature Selection گرفت و مدل دیگری را با Featureهای مهم‌تر ساخت؛ اما این انتخاب باید دوباره روی Validation سنجیده شود، چون Importance وابسته به همین Dataset و همین Tree است.

۱۹. از خواندن تصویر تا Gray، Edge و Resize

Script اول چند تبدیل پایه را کنار هم می‌گذارد: خواندن تصویر، تبدیل به Grayscale، پیداکردن Edge با Canny و تغییر اندازه. این‌ها مرحله‌های Feature Engineering یا آماده‌سازی ورودی در مسائل Computer Vision هستند؛ خودشان یک Classifier کامل نیستند.

Grayscale

Canny

۲۰. فریم‌های Webcam با VideoCapture

Script دوم به‌جای یک فایل ثابت، از Camera شمارهٔ صفر فریم می‌گیرد. هر فریم همان Array تصویری است؛ بنابراین تبدیل Gray و Canny روی آن هم اجرا می‌شود. Loop با کلید Escape، یعنی کد ۲۷، متوقف می‌شود.

import cv2

capture = cv2.VideoCapture(0)

while True:
    ok, bgr_frame = capture.read()
    if not ok:
        break
    gray = cv2.cvtColor(bgr_frame, cv2.COLOR_BGR2GRAY)
    edges = cv2.Canny(gray, 50, 150, apertureSize=3)

    cv2.imshow("Image", bgr_frame)
    cv2.imshow("Gray", gray)
    cv2.imshow("Edges", edges)

    if cv2.waitKey(1) == 27:
        break

capture.release()
cv2.destroyAllWindows()
اصلاح کوچک نسبت به Script جلسه: مقدار Boolean برگشتی از read اینجا بررسی شده است. اگر Camera باز نشود یا فریمی نرسد، تبدیل رنگ روی None خطا می‌دهد؛ پس این Guard لازم است.

۲۲. خودآزمایی جلسه

چرا Decision Tree را مدل قابل تفسیر می‌دانیم؟

چون Prediction یک نمونه را می‌توان به مسیر مشخصی از شرط‌های Root تا Leaf نسبت داد. البته درخت خیلی عمیق هنوز سخت‌خوان و مستعد Overfitting است.

Candidate Threshold برای Feature عددی چطور ساخته می‌شود؟

مقدارهای متمایز مرتب می‌شوند و نقطه‌های میانی بین مقدارهای متوالی بررسی می‌شوند. سپس Impurity وزنی Childها برای هر Candidate محاسبه می‌شود.

Impurity صفر چه معنی دارد؟

همهٔ نمونه‌های Node از یک Class هستند. آن Node خالص است و از دید Classification جداسازی بیشتری لازم ندارد.

فرق min_samples_split و min_samples_leaf چیست؟

اولی می‌گوید Node برای اینکه اصلاً Split شود حداقل چند نمونه لازم دارد؛ دومی حداقل تعداد نمونه‌ای است که باید بعد از Split در هر Leaf باقی بماند.

چرا Report برابر ۱٫۰۰ در Notebook کافی نیست؟

چون پیش‌بینی روی همان X انجام شده که مدل با آن Fit شده است. باید عملکرد روی دادهٔ دیده‌نشده سنجیده شود.

فرق BGR و RGB در این مثال چیست؟

OpenCV تصویر را BGR می‌خواند، اما Matplotlib RGB نمایش می‌دهد. بدون تبدیل، Channel قرمز و آبی جابه‌جا دیده می‌شوند.

آیا اجرای GPU به‌تنهایی ثابت می‌کند Model بهتر است؟

۱. ارزیابی؛ هر Metric یک سؤال متفاوت است

به‌جای حفظ‌کردن فرمول‌ها، سؤال هر Metric را به خاطر بسپار. یک Metric اصلی برای انتخاب مدل داشته باش و دو Metric نگهبان برای اینکه نقطهٔ ضعفش پنهان نماند.

RMSE
Error معمولاً چقدر است؟
هم‌واحد با y؛ Error بزرگ را بیشتر جریمه می‌کند.
MAE
قدر مطلق Error معمولاً چقدر است؟
از RMSE در برابر Outlier مقاوم‌تر است.
R²
از حدس Mean بهتر شده‌ام؟
منفی یعنی حتی Baseline میانگین بهتر بوده است.
MAPE: درصدی و خواناست، ولی وقتی y صفر یا نزدیک صفر باشد قابل اعتماد نیست.
Precision
از Positiveهای گفته‌شده چندتا درست بود؟
وقتی False Positive گران است.
Recall
از Positiveهای واقعی چندتا پیدا شد؟
وقتی False Negative خطرناک است.
F1 / Fβ
تعادل Precision و Recall چطور است؟
با β می‌توانی وزن Recall یا Precision را بیشتر کنی.

Accuracy را تنها نگذار. Balanced Accuracy، Macro F1 و Average Precision را ببین؛ Split را Stratified انجام بده و Threshold را بر اساس هزینهٔ FP/FN روی validation تنظیم کن.

مثال کلاس: مدل «همیشه سالم» روی ۹۹۰ سالم و ۱۰ بیمار، Accuracy=99% دارد ولی Recall بیمار صفر است.
Metricهای تکمیلی که چه زمانی لازم می‌شوند؟
Metricزمان استفادهدام
Balanced AccuracyClassهای نامتوازنProbability quality را نمی‌سنجد.
Average PrecisionPositive نادر و Rankingبه Prevalence حساس است.
ROC-AUCمقایسهٔ Ranking روی Thresholdهادر Imbalance شدید می‌تواند خوش‌بینانه باشد.
Log Lossکیفیت Probability و Confidenceپیش‌بینی مطمئن ولی غلط را شدید جریمه می‌کند.
MCCخلاصهٔ متوازن Binary Classificationتفسیرش برای مخاطب غیرفنی سخت‌تر است.
MedianAE / Max ErrorRobustness یا Worst case در Regressionبه‌تنهایی تصویر کامل نمی‌دهند.

۲. آماده‌سازی داده؛ همه‌چیز داخل Pipeline

هر Stepی که چیزی از داده یاد می‌گیرد—Mean، Min/Max، Median، همسایه یا Feature mapping—باید فقط روی train fit شود. Pipeline این قرارداد را خودکار نگه می‌دارد.

۳. ساخت مدل؛ Curve بساز، Complexity را مهار کن

PolynomialFeatures Model جدید نیست؛ Feature space را گسترش می‌دهد تا یک Linear Model بتواند Curve یاد بگیرد. مشکل اصلی، رشد سریع تعداد Featureها و Overfitting است.

x
←
1, x, x², …
←
Ridge / Lasso
←
Validation
بدون Penalty. Baseline شفاف است، ولی Featureهای هم‌بسته و degree بالا می‌توانند Coefficientها را ناپایدار کنند. اول از این شروع کن، نه اینکه همیشه با آن تمام کنی.
L2 Regularization. همهٔ Coefficientها را Shrink می‌کند و برای Polynomial Featureهای هم‌بسته انتخاب پیش‌فرض خوبی است. Hyperparameter اصلی: alpha.
L1 Regularization. می‌تواند بعضی Coefficientها را صفر کند. Hyperparameter اصلی alpha است؛ Scaleکردن Featureها قبلش اهمیت دارد.
degree
Curve چقدر انعطاف داشته باشد؟
با CV انتخاب شود؛ عدد بزرگ‌تر الزاماً بهتر نیست.
interaction_only
فقط Interaction می‌خواهم؟
Powerهای تکراری مثل x² را حذف می‌کند.
include_bias
ستون یک‌ها لازم است؟
وقتی Model Intercept دارد معمولاً False شفاف‌تر است.
نتیجهٔ فایل کلاس: degree=8 فقط بهترین Candidateهای امتحان‌شده بود؛ Test R² هنوز منفی ماند. «بهترین بین گزینه‌ها» با «مدل خوب» یکی نیست.

LocalOutlierFactor چگالی محلی هر Sample را با همسایه‌هایش مقایسه می‌کند. پارامترهای مهم: n_neighbors، metric، contamination و novelty. چون Distance-based است، Scaling مهم است. novelty=False برای Outlier detection روی Data موجود و novelty=True برای Predict روی Sampleهای جدید است.

۴. اعتبارسنجی و Tune؛ آینده را لو نده

برای Classification از Stratification استفاده کن. اگر Group داری، Sampleهای یک Group نباید هم‌زمان در train و validation پخش شوند.

Shuffle نکن. Hold-out انتهایی برای test نهایی و TimeSeriesSplit برای Tune. پارامترهای مهم: n_splits، test_size، max_train_size و gap.

Walk-forward به زبان ساده
Train گذشته
←
Gap اختیاری
←
Validation آینده
GridSearchCV در حد لازم

تمام Combinationهای یک Grid را با CV می‌سنجد. مهم‌ترین ورودی‌ها: param_grid، scoring، cv، n_jobs و refit. پارامتر Pipeline با الگوی step__parameter نوشته می‌شود.

۵. تحویل مدل؛ Artifact فقط یک فایل نیست

Pipeline کامل را ذخیره کن تا Imputer، Scaler، Feature Engineering و Model با هم بمانند. کنار Artifact هم Recipe آموزش و Versionها را نگه دار.

ساده و Python-native. joblib برای Arrayهای بزرگ و Memory mapping بهتر است؛ هر دو می‌توانند هنگام Load کد اجرا کنند و فقط برای منبع Trusted هستند.
امن‌تر از فرمت‌های Pickle-based. Typeهای ناشناخته قبل از Load قابل بررسی‌اند، ولی پوشش Typeها محدودتر است و Environment مشابه لازم می‌ماند.
برای Inference مستقل از Python. Runtime سبک‌تر، اما همهٔ Modelها و Componentهای سفارشی قابل تبدیل نیستند.
Environment

Python، sklearn، NumPy و SciPy را Pin کن.

نام، ترتیب، Type و Unit Featureها.

چرا این Model انتخاب شد؟

خودآزمایی سریع

چرا Accuracy=99% ممکن است Model بدی باشد؟

اگر Positive بسیار نادر باشد، Model می‌تواند همه را Negative بگوید و Accuracy بالا بگیرد، ولی Recall Positive صفر باشد.

فرق fit_transform روی train و transform روی test چیست؟

train پارامترهای Transformer را یاد می‌دهد؛ test فقط با همان پارامترهای یادگرفته‌شده تبدیل می‌شود.

چرا degree=8 با R² منفی هنوز خوب نیست؟

فقط بین Candidateها بهتر بوده؛ R² منفی یعنی Baseline پیش‌بینی Mean روی test بهتر عمل کرده است.

چه زمانی Ridge را به LinearRegression ترجیح می‌دهیم؟

وقتی Featureها زیاد یا هم‌بسته‌اند، به‌خصوص بعد از PolynomialFeatures، و می‌خواهیم با L2 Coefficientها را پایدارتر کنیم.
